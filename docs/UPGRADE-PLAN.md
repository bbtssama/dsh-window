### 实施中发现并修正的两个结构性问题（计划里没预见）

1. **插件实例是进程级单例**，而状态（工作区、当前笔记、正文、选中、版本、初始化 promise）本质上是**每会话**的。原实现只保存一份 → 第二个会话根本无法服务。现在改为每会话一条记录，在**一个全局串行点**内换入换出（`activate`/`saveCurrent`），并且每个工具/RPC 的**整个执行体**都在这把锁内（`registerToolLocked`/`handleLocked`）。持锁贯穿整个函数体，才能保证换指针期间没有别的操作插进来。
2. **`listNoteDirs()` 把任何失败都当成"没有笔记"**。会话目录不存在是正常的空态，但 fs 服务坏掉时会**静默清空**整个笔记空间。现在只有 `FS_NOT_FOUND`/`ENOENT` 视为空，其余一律抛错。

### 剩余工作

1. **斜杠命令 `/note`**：作为"我想用笔记"的显式入口（`commands` 服务可用时注册；服务缺失则跳过）。
2. **重启 dsh 后的真机验证**：本次是 host 改动，不重启不生效。会话 id 进入路径后，请确认：新会话默认空态、创建/切换/导入/清空/删除都正常、旧笔记被迁移到 `<会话id>/note/` 下且 git 历史连续。
3. 可选：把"卡片默认出现空态"改成"仅当有笔记或敲过 /note 才出现"（见第 9 节 A/B 决定）。

## 1. 为什么要改（现状的问题）

| 现状 | 问题 |
| --- | --- |
| 存储 = `<工作区>/dsh-note/note.md` | **一个工作区只有一份笔记**：同一工作区的多个会话必然共享，只能靠"归属会话 + 拒绝陌生调用"这种**权限**手段兜住 |
| 归属 = 记录里的一个 `sessionId` | 抢归属、泄漏、新会话意外激活，全都源于"多人抢一份文件"这个结构 |
| 只有一份笔记 | 无法按主题拆分；清空/删除只能动同一份文件 |
| 面板只有"编辑/保存/选中/清空/重载" | 没有"笔记"这个概念本身的操作（新建/切换/导入/删除） |

**根因是结构，不是权限**：权限控制永远要回答"谁能看"，而按会话隔离的回答是"**别人的东西根本不在你的路径里**"。

## 2. 目标与非目标

### 目标
1. **存储按会话隔离**：另一个会话的内容**不在本会话的路径下**，不依赖任何权限判断。
2. **一个会话多份笔记**：可新建、切换、清空、删除、导入。
3. **为未来的插件功能留出结构**：`dsh-window/` 作为这个插件的工作区根，笔记只是第一个模块。
4. **对 LLM 提供完整工具面**：创建/导入/清空/删除/列举/切换/读写/划线管理，全部有工具、有 Schema、有渲染。
5. **面板升级**：会话内笔记选择器 + 新建（空/粘贴/拖拽/文件选择）+ 清空 + 删除 + 重命名。
6. **不破坏已有内容**：现有 `dsh-note/note.md` + `.note-state.json` + 独立 git **原样迁移**进新结构（含 git 历史）。

### 非目标（本次不做，避免摊大）
- 多笔记之间的交叉引用/双链。
- 笔记协作（多人同时编辑同一份）——按会话隔离后天然单写者。
- 富文本/WYSIWYG 编辑器（仍是 Markdown 源码 + 卡片渲染）。
- 云端同步。

## 3. 新存储布局

```
<工作区>/dsh-window/                     ← 插件根目录（未来放别的功能模块）
└── note/                                ← 笔记模块
    └── <sessionId>/                     ← 每个会话一个工作空间（会话隔离在这里）
        ├── .session.json                ← 本会话的元数据：当前打开的笔记名
        ├── note/                        ← 一份笔记 = 一个目录
        │   ├── note.md                  ← 正文（卡片显示的就是它）
        │   ├── .note-state.json          ← 选中记录
        │   ├── .note-state.bad.json      ← 损坏备份（可选）
        │   └── .git/                     ← 这一份笔记自己的 git 历史
        └── 会议纪要/
            ├── note.md
            └── .git/
```

要点：
- **会话隔离由路径完成**：`.../note/<sessionId>/`。其他会话的路径不在这棵子树里。
- **笔记名 = 目录名**。名字做安全化处理（`sanitizeNoteName`：去路径分隔符、控制字符，长度限制，CJK 保留），并防重名。
- **每份笔记一个 git**：清空笔记保留历史（提交一次空内容/模板），删除笔记则整个目录连同 `.git` 一起消失——符合用户要求。
- 文件名固定为 `note.md`（不随笔记名变），这样卡片/工具/迁移逻辑都不必处理"文件名"这个自由度；用户可见的名字就是目录名。

### 迁移（一次性、幂等）
1. 若 `<工作区>/dsh-note/` 存在，且 `<工作区>/dsh-window/note/<ownerSessionId>/note/` 不存在：
   把 `dsh-note/` 的 `note.md`、`.note-state.json`、`.git/` **移动**（`rename` 优先，失败则复制）到新位置；
   把 `<ownerSessionId>` 定为迁移后的归属会话（沿用现有 `sessionId`；没有则用第一个调用它的会话）。
2. 迁移前先做一次 git 提交（"迁移前快照"），保证历史连续。
3. 迁移成功后保留空的 `dsh-note/`（不删目录，避免用户觉得数据没了），并写一个 `MOVED.md` 指路？——**改成：不写额外文件，迁移结果通过 `note_diag` 和卡片面板展示**。
4. 迁移只在**明确动作**时发生（任一会话的工具调用/RPC），不在插件加载时静默搬文件。

## 4. Host 侧 API

### 4.1 会话与笔记的解析
- `sessionIdOf(caller)`：工具调用 → `exec.agent.session.header.id`；RPC → 请求里的 `sessionId`；命令 → `invocation.agent`。
- **没有会话 id 就拒绝**（工具抛错、RPC 回 `{ error: 'no-session' }`）。不再有"猜会话"的路径（现状已删，继续保持）。
- `base = workspaceRoot(caller)`（政策解析）→ `sessionRoot = base/dsh-window/note/<sid>`。
- `activeNote`：读 `<sessionRoot>/.session.json`；不存在则取**列表里第一个**笔记；都没有则视为"本会话还没有笔记"。

### 4.2 工具（对 LLM）

**保留并改造（全部作用于"本会话当前打开的笔记"）**
`note_read`、`note_write`、`note_patch`、`note_patch_many`、`note_find`、`note_get_selections`、`note_take_new_selections`、`note_add_selection`、`note_remove_selection`、`note_set_color`、`note_clear_selections`、`note_commit`、`note_checkpoint`、`note_diag`

**新增**
| 工具 | 作用 | 关键参数 |
| --- | --- | --- |
| `note_list` | 列出本会话的所有笔记，标注当前打开的是哪个 | 无 |
| `note_create` | 新建笔记；支持**从指定文件导入**创建 | `name`、`from`（可选，绝对/相对路径）、`mode`（`copy` 原样复制 / `convert` 读为文本）、`open`（默认 true） |
| `note_open` | 切换当前打开的笔记 | `name` |
| `note_clear` | 清空当前笔记正文，**保留 git 历史**（自动提交一次"清空"） | `confirm`、`title`（可选，清空后写入的标题模板） |
| `note_delete` | **完全删除**某份笔记（整目录含 `.git`） | `name`、`confirm: true`（必须显式确认） |
| `note_rename` | 重命名（目录改名，git 不变） | `from`、`to` |
| `note_import` | 把外部文件内容**导入到当前笔记** | `from`、`mode`（`append` 追加 / `replace` 覆盖） |
| `note_export` | 把当前笔记导出到外部路径 | `to` |

说明：
- 破坏性操作（`note_clear`、`note_delete`）**必须显式确认**，并返回被删除的内容摘要与 git 状态，便于事后追溯。
- `note_create(from=...)` 的 `convert` 模式：对 `.md`/`.txt` 原样读；对二进制拒绝并提示（保持明确）。
- 全部工具沿用现有的"响亮失败"风格：会话不明、笔记不存在、名字非法 → 抛错并说明怎么修。

### 4.3 RPC（对卡片）
保留 `state` / `saveText` / `addSelection` / `removeSelection` / `clearSelections` / `commit` / `asset` / `reload`，全部**隐式作用于本会话当前笔记**（请求必须带 `sessionId`）。

新增：
| 方法 | 作用 |
| --- | --- |
| `listNotes` | `{ notes: [{name, active, lines, bytes, commitHash, savedAt}], active }` |
| `createNote` | `{ name, source }`，`source` 支持：`empty` / `text`（粘贴）/ `upload`（base64 文件）/ `path`（工作区路径） |
| `selectNote` | 切换当前笔记 |
| `clearNote` | 清空正文（保留 git） |
| `deleteNote` | 删除整目录（含 git），带 `confirm` |
| `renameNote` | 重命名 |
| `importNote` | 向当前笔记导入：`text` / `upload` / `path`，`mode: append\|replace` |

上传/粘贴统一走 **base64**（`asset` 已有 base64 工具函数），宿主负责写盘；大小上限 8 MB，超限明确报错。

## 5. 面板（用户手动操作）升级

```
┌ 笔记 ─────────────────────────────  ▾ ┐   ← 折叠
│ [笔记 ▾]  [＋新建] [导入] [⋯]          │   ← 新增：会话内笔记选择器 + 操作
├───────────────────────────────────────┤
│ （正文/编辑器，保持现有能力）          │
├───────────────────────────────────────┤
│ 编辑 保存 选中 清空 重载              │
└───────────────────────────────────────┘
```

1. **笔记选择器**：下拉列出本会话所有笔记（名称 + 行数 + 是否有未提交改动），点击切换。
2. **新建**：
   - 直接输入名字 → 空笔记（写入标题模板）；
   - **粘贴**：对话框里粘贴 Markdown 文本；
   - **拖拽**：把文件拖到卡片上（卡片高亮）→ 以文件内容（文本）或原文件（二进制）创建；
   - **文件选择**：`<input type=file>`（浏览器标准，Windows 下即"选择文件"对话框）。
3. **导入**：向当前笔记追加/覆盖（同样支持粘贴/拖拽/选择文件）。
4. **清空**：二次确认；提示"git 历史保留"。
5. **删除**：二次确认；提示"整个目录（含 git）都会被删除"；删除后自动切到下一个笔记；本会话没有笔记时卡片回到"空态"。
6. **重命名**。
7. 现有能力全部保留：长按选中、纺锤、颜色、表格、图片、mermaid、编辑/保存/重载、状态栏。

### 空态
本会话没有任何笔记时，卡片显示：一句说明 + `[新建笔记]` `[从文件导入]` 两个按钮（**不再默认创建**）。

### 显式入口（避免"新会话自己出现卡片"）
- 卡片**只在以下情况出现**：本会话已有至少一份笔记；或用户显式要求（斜杠命令）。
- 注册斜杠命令 **`/note`**：`/note`（列出/打开）、`/note new <名字>`、`/note open <名字>`。这是"我想要笔记"的最短路径，也是 agent/用户都能用的显式动作。

## 8. 风险与取舍（诚实清单）

1. **迁移是文件移动**：失败必须有明确报错与回退（先复制后删、失败保留原目录）。迁移前自动 git 提交一次快照。
2. **多笔记 = 多 git 仓库**：每个笔记目录一个 `.git`，磁盘上会有多份历史；这是"删除笔记连历史一起删"的代价，符合用户要求。
3. **会话 id 出现在路径里**：会话被删后目录仍在（内容不丢），但那个会话再也回不来（新会话是新路径）。需要一个"导入/接管"路径：**新会话可以通过 `note_create(from=<旧会话的 note.md 路径>)` 或面板"从文件导入"把旧内容拿过来**——这就是跨会话迁移的正式方式（显式、可见、不自动）。
4. **面板复杂度上升**：本次一次做完，用户用后自己挑留哪些（用户明确要求这样）。
5. **`/note` 命令依赖 `commands` 服务**：服务缺失时静默跳过，不影响其余功能。
