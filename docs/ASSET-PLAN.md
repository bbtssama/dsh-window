# 笔记与静态素材：重构设计 v2（锁定约束版，不含实现）

> v1 里我列了三种模式，**按你给的三条硬约束，B（就地引用）与 C（指针指向原目录）都被否决**
> —— 任何素材都必须**镜像进 `dsh-window`**，渲染时**不读 `dsh-window` 之外的任何路径**。
> 本文是按这三条约束收敛后的最终布局：
>
> 1. **必须创建镜像**，资产等所有东西都在 `dsh-window` 里；
> 2. 一个文件夹里有多个 `.md` 时，**不能各复制一份素材** → 素材要被**共享**；
> 3. **笔记本体（.md）一定有独立的 `.git`**；**所有素材用一个更粗粒度的 `.git`**。

---

## 1. 目标布局

```
<工作区>/dsh-window/
├── note/<会话 id>/<笔记名>/          ← 一份笔记一个目录
│   ├── note.md                      ← 正文（含它的 .git ✓ 每份笔记独立）
│   ├── note.json                    ← 新增：{ assetRoot, origin? }（见 §3）
│   ├── .note-state.json / .note-view.json
│   └── .git/                        ← 只管 .md + 状态，**永不含二进制素材**
└── assets/                          ← 素材区：**所有资产都住这里**
    ├── .git/                        ← 一个粗粒度仓库，管全部素材
    ├── index.json                   ← 素材根清单（见 §4）
    └── <素材根 id>/…                 ← 按**原始目录结构**镜像，多个 .md 共享同一份
        ├── img/a.png
        └── assets/b.png
```

- **两个仓库、两种粒度**：笔记仓库回答"这份笔记的内容怎么变的"；素材仓库回答"素材什么时候进来的"。
- 一个素材根 = 一个源文件夹 ✓。同一文件夹里的 **N 个 `.md` 共用同一个素材根** ✓ → **只镜像一份** ✓（这正解决了 A 方案"多个 .md 各复制一份 assets"的问题）。
- `dsh-window` 整棵树可以整体搬走：笔记与素材都在里面，引用用**相对 `dsh-window` 的路径**记录 ✓。

---

## 2. 素材根 id（保证"多 .md 共享一份"）

```
<清洗过的目录名>-<源绝对路径的 8 位 hash>      例如  linux-notes-3f9a2c71
```
- 同一个源目录重复导入 → **同一个 id** → 复用已有镜像 ✓ 不重复复制 ✓。
- 不同源目录同名 → hash 不同 ✓ 不串味 ✓。
- 记录在 `assets/index.json` 与每份笔记的 `note.json` 里：

```jsonc
// assets/index.json
{ "v": 1, "roots": [
  { "id": "linux-notes-3f9a2c71", "label": "Linux 学习", "source": "D:/notes/linux",   // 仅出处，渲染永不依赖
    "mirroredAt": "2026-09-14T…", "files": 41, "bytes": 18324992, "mode": "referenced" }
]}

// note/<会话>/<笔记名>/note.json
{ "v": 1, "assetRoot": "assets/linux-notes-3f9a2c71", "origin": "D:/notes/linux/README.md" }
```
`assetRoot` 一律写成**相对 `dsh-window` 的路径** ✓（整棵树可搬 ✓）。根目录绝不能写成 `dsh-window` 之外的东西 —— 见 §6 的硬校验。

## 3. 引用怎么解析（阶梯，且**绝不越界**）

`![](./img/a.png)` 这类的解析顺序：

1. **笔记目录**：`<笔记目录>/img/a.png` —— 兼容"素材本来就在笔记目录里"的既有笔记（= 现状，零迁移）；
2. **笔记的素材根**：`dsh-window/<assetRoot>/img/a.png` ✓（主流路径）；
3. **素材区兜底**：在所有素材根里按**同样的相对路径**找（`assets/*/img/a.png`）✓ —— 处理"多个笔记来自同一文件夹、但笔记只认自己那一个根"的边角情况。

**硬约束**：三步解析出的最终路径若落在 `dsh-window` 之外 → **直接拒绝**（返回"越界，已拒绝"而不是尝试读取）。
这条要写进 `asset` 的实现里（现在它是能读到 `C:/Windows/win.ini` 的，实测过）——**镜像化的前提是解析器不能开后门**。

`.md` 里的引用**不需要改写**（阶梯兜住）✓。
可选动作「改写为相对笔记的路径」（`../../../../assets/<id>/img/a.png`）留给"希望这份 .md 在外编辑器里也能看图"的人 ✓，默认**不改写**（保持原文干净）。

## 4. 导入流程（多 `.md` 共享素材 + 只镜像一次）

1. **选目录** → host 列出其中的 `*.md`（含子目录，可勾选）→ 用户**多选**要建笔记的文件；
2. **算出/复用素材根 id**（§2）✓；
3. **决定镜像范围**（导入时的选项，默认第一项）：
   - `referenced`（默认）：扫描所有选中 `.md` 里的本地引用（`![]()`、`<img src>`、`<video>`、`[]()` 里的媒体后缀等）→ 只镜像**被引用到的文件**；
   - `all`：整个目录（排除 `.git/`、`node_modules/`、`*.tmp`、`__pycache__` 等）→ 最省心，适合中小目录；
   - 两者都可以设置**单文件上限 / 总量上限**，超限跳过并在结果里列出（不静默）。
4. **复制进 `assets/<id>/…`，保持原始相对结构** ✓（这是"相对路径仍然成立"的关键）；
5. **素材仓库提交一次**：`assets: 导入 <label>（N 文件 / X MB，模式 referenced）` ✓；
6. **为每个选中的 `.md` 建一份笔记**：正文复制进 `note/<会话>/<名字>/note.md` ✓、`git init` ✓（每份笔记独立仓库 ✓）、`note.json` 写入 `assetRoot` ✓；
7. 返回一张清单：每个笔记 → 引用总数 / 已镜像 / 未镜像（附原因）✓。

**增量同步**（`同步素材` 动作）：按 mtime+size（必要时 hash）只复制新增/变化的文件 → 素材仓库再提交一次 ✓；源目录里被删的文件**不跟着删** ✓（镜像只增不减 ✓，避免悄悄弄坏历史笔记），在 `note_diag` 里列为"源已删除"。

## 5. 两个仓库的边界（回答"为什么这样分"）

| | 笔记仓库（每份一份） | 素材仓库（一个） |
| --- | --- | --- |
| 位置 | `note/<会话>/<笔记名>/.git` | `assets/.git` |
| 跟踪 | `note.md`、`note.json`、`.note-state.json` | `assets/**`、`index.json` |
| 提交时机 | 内容改动（现状不变，静默落盘 + 手动/自动提交） | 导入 / 同步 / 手动 |
| 体积 | 永远很小、diff 可读 | 会随素材累积（二进制） |
| 为什么要分开 | 你要求"笔记本体一定有自己的 .git" ✓，且**它不该被图片的二进制历史拖大** ✓ | "素材用一个更粗粒度的 .git" ✓ |

> 一个副作用值得记下：**素材被删/被换，笔记仓库不会知道** —— 所以 `note_diag` 要同时报"引用 → 命中"的对照表，让"图没了"这类问题一眼可见。

## 6. 护栏（这几条不做，方案会反过来伤人）

1. **解析越界拒绝**（§3）—— 镜像化之后，读取范围必须收紧到 `dsh-window` 内；
2. **`assetRoot` 只允许写 `dsh-window/assets/**`** —— 工具面（`note_asset_root`）要硬校验；
   `assetRoot` 一旦能被模型单方面放大，等于把整台机器的读权限交给卡片；
   而且**改动要显式、要写进会话状态、要在卡片上可见**（谁改了素材根，用户看得见）；
3. **素材仓库体积**：单文件/总量上限 + 超限提示；可选"跳过 >X MB 的文件"；硬链接（同盘 NTFS，免管理员）作为可选省空间手段；
4. **名字安全**：素材根 id 由目录名清洗 + hash 生成 ✓ 不接受用户直接给的路径片段（防 `..`）；
5. **`--all` 模式**要有排除表与上限，不能把用户整个家目录吞进仓库。

## 8. 与 v1 相比被否决的选项（留个记录，别下次又绕回来）

- **就地托管（不复制）**：被否决 —— 素材必须在 `dsh-window` 里（你的第 1 条约束）；
- **指针指向原目录**：同上被否决。它还有个额外毛病：原目录被移动/删除就断链；
- **`.lnk` 当链接**：`.lnk` 是 Explorer 的快捷方式，**任何程序都读不进去**，永远只能当面包屑；
- **每个 `.md` 各复制一份素材**：被你的第 2 条约束否决 → 改为"**一个素材根，多个 `.md` 共享**"。

## 9. 需要你点头的两件事

1. **镜像范围默认值**：`referenced`（只镜像被引用的文件，省空间、够用）还是 `all`（整目录，最省心）？我建议 `referenced` + 一键切换。
2. **是否现在开始实现**：范围建议分两步 —— ①先把"导入文件夹（多选 .md）+ 素材根 + 阶梯解析 + 素材仓库"做完；
   ②再做"同步 / 引用对照表 / HTTP 素材路由 / 搬移既有素材"。
